Bug #30: PDF generated, but couldn't be saved to your history
Description: When a user clicks 'Generate PDF', the PDF downloads successfully but the quote history entry fails to save. The "download" action does not create a history record.
Fix (Hybrid Approach):

1. Keep PDF generation in the frontend (fast, scalable, zero server load).
2. Before generating the PDF, call POST /api/quotes to save the history record with source: "download".
3. If the history save succeeds, proceed with client-side PDF generation.
4. If the history save fails (network error), save the quote to a localStorage offline queue.
5. Generate the PDF locally regardless (user experience first).
6. When the user reconnects, sync the offline queue to the server.
7. This ensures history is eventually consistent while keeping PDF generation fast and scalable.
